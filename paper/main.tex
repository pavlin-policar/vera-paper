%% Abstract section.
\abstract{%
Two-dimensional embeddings resulting from dimensionality reduction techniques, such as t-SNE, UMAP, and multidimensional scaling, are widely used in various scientific fields to visualize high-dimensional data. These visualizations provide a useful tool for exploratory data analysis, allowing researchers to identify clusters, outliers, and other interesting patterns in the data. However, interpreting the resulting visualizations can be challenging, as it often requires additional analysis to understand the differences between data points in different regions of the embedding space. To address this issue, we propose VECA (Visual Explanations and Contrastive Analysis), an automatic embedding-annotation approach that generates visual explanations for any two-dimensional embedding. Motivated by insights from social science, VECA is designed to produce informative and contrastive explanations that best characterize distinct regions in the visualization compared to the remainder of the embedding space. Unlike existing approaches, VECA automatically performs both the identification and selection of possible visual explanations according to their information content and contrastive importance, then generates a small but diverse set of informative explanations. We demonstrate the utility of VECA on several high-dimensional datasets, including transcriptomics data.

Our open-source, Python implementation of VECA is freely-available at \url{https://github.com/pavlin-policar/veca}.
}

\section{Visual Explanations}

In this section, we develop a conceptual framework for the automatic generation of visual explanations. Suppose we are presented with a scatter plot corresponding to a two-dimensional non-linear embedding of a high-dimensional data set. The scatter plot shows an apparent cluster in the two-dimensional embedding. A natural question immediately arises:  \textit{"What makes this cluster different from the remaining data points?"} The goal of this work is to develop an automatic visual approach that can aid the user in answering this question.

Given an arbitrary data set $D$ and its corresponding two-dimensional embedding $Y$, our objective is to generate clear and meaningful visual explanations that convey semantic information about the structure of the embedding. As $D$ can contain both continuous and discrete features, we establish a common representation better suited to generating visual explanations. We expand each input variable into a collection of one or more \textit{explanatory variables}. An explanatory variable is a binary indicator variable indicating group membership, where the groups are derived from the input variables. For instance, a categorical variable with three categories will be expanded into three explanatory variables, each indicating sample membership to a particular category (i.e., one-hot-encoding). For continuous variables, the groups correspond to value ranges (i.e., discretization). This common representation enables a uniform treatment for both variable types. Each explanatory variable is associated with a corresponding \textit{region} $r$, representing collections of spatially localized points in the embedding space where the explanatory variable is enriched. Finally, we define \textit{visual explanations} as collections of regions that convey helpful information about the embedding structure to the end-user.

Our conceptual framework can be split into three distinct phases: (i) region construction, (ii) explanation construction, and (iii) explanation selection. We next describe each of these phases in detail.

\subsection{Region construction}

Regions serve as the fundamental building block for constructing visual explanations. Regions represent collections of data points in the embedding sharing a common characteristic. Regions can be represented in a myriad of ways. However, one simple approach is to represent each region as a collection of one or more polygons in the embedding space, each encompassing a set of data points. Ideally, a region should contain all data points with that characteristic and exclude all other data points. However, in most real-world embeddings, a clean separation between points with some particular feature value and those without rarely exists. It is easy to see that prioritizing this criterion would lead to overly fragmented, complex polygons in most real-world embeddings, resulting in difficult-to-interpret regions, providing little benefit to the end user. Instead, we prefer simpler, visually-appealing regions that may not perfectly encompass \textit{all} data points but still provide \textit{generally} accurate representations.

\subsection{Explanation construction}

Once we have determined regions for each of our explanatory variables, we would like to show these to the user in a concise and informative manner. While we could show individual explanatory variables to the end user, this would likely overwhelm the user with a large number of plots, requiring the user to inspect each one by one.
Instead, we combine explanatory variables into a smaller number of visual explanations and rank these according to their information content.
Visual explanations should follow two general guidelines:
\begin{enumerate}
  \item We want to avoid cluttering explanations with too many explanatory variables or displayed regions, as this is difficult to understand, and
  \item we want to avoid visual explanations where the included regions have a high degree of overlap, which can make it difficult to distinguish between different regions and render the visualizations illegible.
\end{enumerate}
Ideally, our visual explanations should be visually appealing, contain a small number of explanatory variables, and include regions with minimal overlap.

\subsection{Explanation selection}

In order to determine what constitutes a good explanation, it is essential to determine our goals, i.e., what kind of information are we trying to convey to the user. This will be the driving factor in determining the quality of an explanation. Miller~\cite{Miller2019} suggests that explanations can answer three types of questions: \textit{what}, \textit{how}, and \textit{why} questions. In the context of visual explanations, answering \textit{how} questions would be challenging as it requires reasoning about the causal chain leading to a particular sample having a specific feature value, which is out of the scope of this paper. Therefore, we will focus on answering \textit{what} and \textit{why} questions through contrastive and descriptive visual explanations.

A \textit{contrastive visual explanation} aims to answer the \textit{why} question, \textit{``Why are these samples different from the other samples with regard to a particular variable?''}, or put another way, \textit{``Where do the different variable values occur?''}. To generate explanations of this kind, we need only include all explanatory variables corresponding to a particular input variable.

A \textit{descriptive visual explanation} aims to answer the \textit{what} question, \textit{``What makes these samples unique?''}.
These kinds of explanations can be highly diverse and typically require a larger number of explanatory variables than contrastive explanations, as describing the unique properties of a particular object without an explicit reference point requires more explanatory causes.

Explicitly stating the goals of each visual explanation type, we can now set about laying guidelines to what constitutes a good visual explanation. An explanation evaluation mechanism is essential.
While the explanation construction process generates a large number of potential visual explanations, many of these explanations may not be particularly useful for the information we are trying to convey.

Additionally, we wish to avoid overwhelming the user with too many visual explanations.

\section{Methods}

In the previous section, we laid out the conceptual framework for visual explanations. In this section, we describe \textit{Visual Explanations and Contrastive Analaysis (VECA)}, our fully-automated approach for generating visual explantations for arbitrary two-dimensional embeddings.

\subsection{Region construction}

Our region construction approach is comprised of extracting contours from a kernel density estimate. We construct regions in the following way. First, we extract all potential explanatory variables from the input data. These can correspond to specific values, sets of values, or ranges of values. The goal is to derive explanatory features that can be useful in understanding the different spatial regions of the embedding. Next, using these explanatory variables, we generate explanatory regions, represented by collections of polygons, which correspond to spatial regions in the space that are enriched with a particular explanatory variable. Our approach can produce overfragmented regions, so a post-hoc merging proceedure is applied. This both reduces the number of possible explanatory regions and improves visual coherence by merging highly-overlapping regions. We describe each of these step in detail.

\subsubsection{Extracting explanatory variables}

The input data set can contain both discrete and continuous variables. Since we want to explain the embedding in terms of the different values or ranges of values of the input variables, we expand each input variable into a collection of explanatory variables. For continuous variables, we use $K$-Means quantization to split the values into $K$ discrete intervals. By default, we split into 5 bins, corresponding to the typical five-point scale: ``very low'', ``low'', ``medium'', ``high'', and ``very high''. Dicrete varaibles are one-hot encoded, resulting in $K$ different explanatory indicator variables, each corresponding to a particular categorical value of the input variable.

\subsubsection{Extracting explanatory regions}
\label{sec:kde_estimation}

After extracting explanatory variables, we determine the regions of the space where these explanatory variables are enriched.

The first step in our approach is to identify the scale of the embedding. Different embedding algorithms produce different embeddings that can span different scales, e.g., one embedding may span from -5 to 5 along its dimensions, while another may span from from -50 to 50. Additionally, using the same scale may not make sense for data sets of different sizes. For instance, in a dataset with 50 samples, we are likely to be interested in groups of 10-20 points, while in a dataset containing 2 million samples, these small groups will be of less interest and could be a result of noise. To determine the scale $\sigma$ of each embedding, we first determine the scale of the groups we are interested in. We select $k=\sqrt{N}$, as this is commonly used in KNN classification. We then compute the median distance of each points's $k$-th nearest neighbor and use that as the scale of the embedding.

Next, for each binary explanatory variable, we obtain its kernel density estimate $D$ using a Gaussian kernel with bandwidth $\sigma$. Next, we extract the contours of the density estimate at a user-defined level, typically at $0.25 \cdot \max D$. Note that because the density estimate may be multimodal, e.g., if an explantory variable is enriched in different regions of the space, we may obtain more than one contour. These contours represent the regions which we use in subsequent steps of our analysis and correspond to spatial regions of the space in which each particular explanatory variable is enriched.

\subsubsection{Post-hoc explanatory variable merging}
\label{sec:merge_overfragmented}

It is unlikely that five bins will result in the optimal discretization of any particular continuous variable. It is also unlikely that all categories associated with a particular categorical variable contain entirely unrelated concepts.
The resulting explanatory variables produced by discretization and one-hot-encoding are often overly-fragmentated, resulting in difficult-to-understand and cluttered visualizations. To remedy this, we apply a post-hoc merging procedure to explanatory variables originating from the same input variable. 

For ordinal and continuous variables, we only allow merging consecutive bins. For instance, the discretization $\{ x < 5, 5 \leq x < 6, 6 \geq x\}$ for a continuous variable could be merged into $\{x < 6, 6 \geq x\}$, but not into $\{ 5 \leq x < 6, x < 5 \mid x \geq 6\}$.
The same reasoning applies to ordinal categorical variables, merging only adjacent categories. For instance, the ordinal values $\{1, 2, 3, 4\}$ could be merged into $\{\{1, 2, 3\}, \{4\}\}$, but not into $\{\{1, 4\}, \{2, 3\}\}$.
We apply no such restriction to nominal categorical variables. E.g., the categorical variable values $\{red, green, blue\}$ could be merged into $\{\{red, green\}, \{blue\}\}$.

Our merging procedure accounts for the spatial location of the regions embedding, and explanatory variables are merged when their corresponding regions exhibit a high degree of overlap.
More concretely, to merge two explanatory variables, we require that their sample overlap is at least 50\%. 
\begin{equation}
\text{overlap}(r_1, r_2) = |r_1 \cap r_2| \notag
\end{equation}
where $r_1$ and $r_2$ are the regions in question, and $|r_1 \cap r_2|$ denotes the cardinality of their intersection.
We also require that the resulting merged region improves the overall purity of the regions by at least 5\%. The purity of a region is defined as
\begin{equation}
\text{purity}(r) = \frac{1}{|r|} \sum_{i \in r} x_i \notag
\end{equation}
where $r$ is the region of interest, $|r|$ is the number of points contained within the region, and $x_i$ is the binary explanatory variable value.
We also require that the merged region does not decrease the spatial localization is not decreased. We measure spatial localization using Geary's C spatial autocorrelation index, defined as
\begin{equation}
C=\frac{N-1}{2 \sum_{ij} W } \frac{\sum_i \sum_j w_{i j}\left(x_i-x_j\right)^2}{\sum_i\left(x_i-\bar{x}\right)^2},\notag
\end{equation}
where $N$ is the number of data samples, $W$ is a weighted adjacency matrix indicating the spatial proximities between data points, and $x_i$ is the feature value of sample $i$.
To compute the adjacency matrix $W$, we utilize the scale $\sigma$ computed in Sec.~\ref{sec:kde_estimation}. For each point, we find all its neighboring data points at a distance of at most $3 \cdot \sigma$. We then compute the probability density function of each of these neighbors using a Gaussian distribution centered at each point using bandwidth $\sigma$.

Merging the regions results in new, larger regions, it may well happen that after one round of merging, that new potential regions may overlap sufficiently to be merged. We perform this merging proceedure iteratively until no further merges can be performed. An example of the overfragmentation and the subsequent merging proceedure is shown in Fig.~\ref{fig:overfragmentation}).

If no particular variable value is localized to a specific region of the embedding space, our merging proceedure could merge all the explanatory variables for a variable, leaving a single region encompassing the entire space. This is desirable, as this indicates that this particular variable holds no bearing when trying to explain the embedding, and is discarded from future consideration for generating visual explanations.

\subsection{Contrastive explanations}

Contrastive explanations of features aim to show where in the embedding different feature values occur.

\subsubsection{Explanation construction}

Generating contrastive explanations is straightforward: for each input variable, we include all its derived explanatory variables. While the different regions may overlap to some degree, our explanatory variable merging proceedure ensures that regions with significant overlap are merged beforehand.

\subsubsection{Explanation selection}

The construction proceedure provides a collection of possible contrastive explanations, one for each input variable. However, some explanations may be more informative than others.
Intuitively, a variable whose values are localized in disjoint regions of the space will be the most informative will be easier to reason about than a variable whose values are distributed more evenly.

To adhere to the principle of ``simple explanations'', we aim to present the user with as few plots as possible. We achieve this by trying to merge regions with sufficient overlap and bipartite mapping between pairs of variables where the edges in the graph are created when there is sufficient overlap between the two regions. By default we require an overlap of at least 95\% of samples in both regions. This can also by used as a visual proxy for identifying feature correlations, in some cases, even non-linear ones.

We want the number of explanatory regions to be manageable. For instance, one region is not particularily informative, while 10 is just too much clutter. We do the Gaussian log-probability.


\subsection{Descriptive Explanations}

With descriptive explanations, we aim to show interesting combinations of explanatory variables such that the resulting plots are as informative as possible. This can include interesting combinations of input variables, and can lead us to uncover interesting relationships between specific variable values.

\subsubsection{Explanation construction}

In descriptive explanations, we are no longer limited to showing explanatory variables from a single input variable, but are free to choose any combination of explanatory variables from any input variable.
It is common that several explanatory variables appear in similar regions of space. For instance, if Fig.~\ref{fig:bipartite_matching}, the three input variables \textit{petal length}, \textit{petal width}, and \textit{species} are highly correlated, and occupy roughly the same regions of the space. To reduce the number of possible visual explanations, we merge together these into a single visual explanation. We only do this when there is sufficient overlap between all pairs of regions. By default, we require that at least 90\% of the encompassed samples are shared between any two pairs of merged regions. Note that the samples need not necessarily have that particular feature value, it only needs to be encompassed by the region.
We also require that the resulting merged cluster has a purity of at least 50\%, i.e., at least 50\% of all samples encompassed within this new region have at least one of the merged variables.
As an additional requirement, we require that each of the resulting clusters has a Geary's C index of at most 0.5. Note that this step is different from the merging proceedure described in Sec.~\ref{sec:merge_overfragmented}, as we do not limit ourselves to merging adjacent bins, or even explanatory variables derived from the same input variable.

Having merged overlapping explanatory variables, we next need to find combinations of these resulting regions so that they produce informative visual explanations.
To avoid cluttering the plot, we want to include variables in each visual explanation so that we have as little overlap as possible. We achieve this by casting this as an graph-independent set problem. We first compute the overlap graph between all explanatory variables, placing an edge between explanatory variables if the overlap between regions exceeds the maximum user-specified threshold, by default 20\% of overlapping samples. Then, the independent sets of this graph are the  find combinations of non-overlapping explanatory variables which do not exceed this prespecified threshold.

\subsubsection{Explanation selection}

Unlike contrastive explanations, descriptive explanations are not limited to including only explanatory regions for a single variable. We instead want to find a combination of explanatory regions, perhaps from different variables, that are as informative as possible. What "informative as possible" means will be defined later on.

Once we have generated the explanatory regions for the relevant variables, we need to rank them according to their importance and informativeness. In order to do this, we take several factors into consideration.
Firstly, we prioritize simple explanations over complex ones. We defined the term ``simplicity'' to mean that it is easily understandable by any end user. Practically, this means preferring explanations containing between 2-5 minimally-overlapping explanatory variables which are highly localized in distinct regions of the space. Additionally, we prefer explanations which cover as much of the embedding as possible.

We achieve this by calculating a score for each embedding layout by considering the following factors. To minimize overlap between regions, we compute the sample overlap between all pairs of regions. To prefer simpler, non-fragmented regions, we calculate the number of polygons each explanatory region contains, and calculate the overall polygon to region ratio for each visual explanation. We prefer explanations where this ratio is closer to one, as this indicates that each explanatory variable has one associated polygon. To maximize embedding coverage, we compute the percentage of total points in the embedding contained within any single region in the visual explanation. To bias explanatrions a smaller number of explanatory variables e.g., between 2-5, we impose a Gaussian prior with $\mu=3$ and $\sigma^2=2$. We then evaluate the probability density function at the number of contained variables in the visual explanations. Intuitively, a higher value will be assigned when the visual explanation contains 3 explanatory variables than when it contains 2 explanatory variables.

Another factor to consider is explanation diversity. Unlike in contrastive explanations, where each subsequent explanation is completely different from one another, and the user is exposed to completely different explanatory variables with each visual explanation, visual explanations can be repeated as often as possible in descriptive explanations. However, intuitively, if a user has seen a particular explanatory variable in the first plot, it would be more informative for the next several visual explanations to not contain this explanatory variable, and prefer explanatory variables that the user has not yet seen.

To achieve this diversity in visual explanations, we develop an iterative visual explanation selection technique. In addition to the layout scores, which can be computed independently for each layout separately, we introduce an explanatory variable penalty which is applied to each visual explanation. Importantly, this penalty depends on the previously selected visual explanations, and consecutive visual explanations which contain repeating visual explanations are heavily penalized. As we don't want explanatory variables to be shown only once, we just want them not to appear in two or three plots in a row, we apply an exponential decay to this variable penalty, such that a variable is no longer penalized after e.g. three visual explanations. This approach enforces diversity in the produced visual explanations and prevents explanatory variables to be repeated too frequently in the visual explanations. Thus, the user can get a better sense of different regions of different explanatory variables while looking at a small number of visual explanations.

\section{Case studies}

In the following, we present three case studies of increasing complexity. We being by running through our analysis on the simple Iris flowers data set~\cite{Anderson1936} which is well-known and easy to understand. We continue with the Wine Quality data set~\cite{Cortez2009}, which contains more input variables, and requires more explanation. We conclude by applying our approach on the large Forest Cover Type data set~\cite{Blackard1999}, containing over half a million data points, and demonstrate how VECA can be used to gain insight into what kinds of errors predictive models may make, and also to understand what kinds of relationships between variables deep-learning models may be learning.

We use default parameter settings in the VECA Python library unless stated otherwise.

\subsection{Iris Flowers}

We walk through the different steps of our analysis using the Iris data set from Anderson~\cite{Anderson1936} as a guiding example. This small data set profiles 150 iris flowers with four continuous variables containing pyhsical measurements of individual flowers (sepal length, sepal width, petal length, petal width) and their corresponding species (Iris Setosa, Iris Versicolor, Iris Virginica).

We first construct a two-dimensional t-SNE embedding of the data set with parameter values metric=cosine, perplexity=30 using the \textsf{openTSNE} library~\cite{Policar2019}. As is common practice with predctive tasks, we do not use the \textit{Species} variable in the emebedding construction. We then explain the resulting embedding using VECA. For this example only, we perform discretization into three bins instead of five, as this better demonstrates the types of things one must take into consideration when construcing visual explanations. The different steps involved in the pipeline are shown in Fig.~\ref{fig:iris_pipeline}.

\begin{figure*}[tb]
  \centering
  \includegraphics[width=\textwidth]{iris_pipeline.pdf}
  \caption{We illustrate the region construction process on the Iris data set.}
  \label{fig:iris_pipeline}
\end{figure*}

The top row of Fig.~\ref{fig:iris_pipeline} shows a standard approach to explaining embeddings in terms of their original features. The points in the scatter plot are colored according to their feature values. This approach works well for a small number of input features, but quickly grows unwieldly as the number of input features increases. Additionally, the plots are typically shown in no particular order, necessitating the inspection of every single input variable. Finally, colors correspond to different feature values and their usefulness is determined by the color palette used. In general, it is fairly easy to distinguish between small and large values of the feature. For instance, the first two panels in the top row of Fig.~\ref{fig:iris_pipeline} show a clear distinction between the left-hand and the right-hand side of the plot in terms of feature values.
However, if the variable distribution is multimodal, it is generally difficult to tell these apart from another, and the colors begin to blend together.
The right-most panel in the top row of Fig.~\ref{fig:iris_pipeline} shows the categorical target variable. While this plot is very clear, these kinds of plots become increasingly difficult to interpret and become increasingly cluttered as the number of categories increases.

The second row of Fig.~\ref{fig:iris_pipeline} shows the initial derived explanatory variables for each input variable. Notice that the third and fourth panels contain regions that contain a high degree of overlap. For instance, in the third panel, the orange region corresponding to the the explanatory variable \textit{sepal length (cm) > 6.55} overlaps almost entirely with the green region corresponding to \textit{5.53 < sepal length (cm) < 6.55}. These two discretizations could be merged into a single interval \textit{sepal length (cm) > 5.53} at minimal loss of information and would declutter the visualization. Indeed, this is exactly what happens in the next step of the VECA pipeline. The third row of Fig.~\ref{fig:iris_pipeline} shows the result of our post-hoc merging proceedure.

The fourth panel in the second row of Fig.~\ref{fig:iris_pipeline} demonstrates a more complex scenario. The blue region corresponding to \textit{sepal width (cm) < 2.85} is localized to the right cluster, and the green region corresponding to \textit{sepal width (cm) > 3.44} is localized to the left cluster. However, the intermediate values corresponding to 
\textit{2.85 < sepal width (cm) < 3.44} in the orange region are present throughout the embedding.
We may consider merging the orange region with the green region, producing an explanatory variable corresponding to \textit{sepal width (cm) > 2.85}, however, this may mislead users to believe there are only two groups of feature values, with high values distributed evelny throughout the entire embedding, and low values appearing only in the right-hand cluster.
Alternatively, we may instead choose to merge the \textit{sepal width (cm) < 2.85} and \textit{2.85 < sepal width (cm) < 3.44} regions, but this may lead to a similarily misleading visualization.
Alternatively, we may choose to leave the regions as they are, but this would result in a highly cluttered visualization.
In VECA, we merge all three clusters into a single explanatory variable. The resulting explanatory variable contains a single region encompassing the entirety of the embedding space. This is not particularily informative and is discarded from any downstream explanations. Other approaches may be possible, but we feel it is better to remove unclear of cluttered visual explanations than to provide misleading or complex explanations.

The third row of Fig.~\ref{fig:iris_pipeline} shows the explanatory variables after our post-hoc merging proceedure. Notice that the first, second, and last panels remain the same as in the row above, as the initially proposed regions have a low degree of overlap. The explanatory variables in the third panel were merged into two explanatory variables, while the explanatory variables in the fourth panel was merged into one, as previously discussed.
Note that the results of our merging proceedure depends on the number of selected bins used during discretization. For instance, had we chosen five bins, as is the default in VECA, the orange region in the fourth panel may have been further split into a left and right region, and the resulting merged region may have been similar to the one shown in the third panel.

The last row of Fig.~\ref{fig:iris_pipeline} shows the generated contrastive and descriptive explanations for this embedding. Due to the small number of variables and their high degree of correlation, there are only two visual explanations for each explanation type. Notice that the first panel in the contrastive explanations display three variables. This is possible as the three variables all contain regions which occupy the same regions of the space. The visual explanations indicate that the classification of Iris flowers is fairly straightforward. One would only need to consider \textit{petal width} and \textit{petal length} to obtain a high degree of accuracy. As this data set is fairly straightforward, the descriptive explanations do not really reveal anything that the contrastive explanations don't.


\subsection{Wine Quality}

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{wine_explanations.pdf}
  \caption{We apply our approach to the wine quality data set. We plot the top four contrastive explanations in panels a-d and the top four descriptive explanations in panels e-h. The contrastive explanations each show where different values of a single input variable appear in the embedding. The descriptive explanations depicted in panels e-h aim to show maximally-informative combinations of the explanatory variables.}
  \label{fig:wine_explanations}
\end{figure*}

The wine quality data set~\cite{Cortez2009} contains 6,497 samples of two common red and white wine variants from a popular winery in the Minho region in Portugal. Each sample is described by 12 physicochemical features, including fixed acidity, residual sugar, and alcohol. The data set is typically used in wine-quality predicton. As before, we generate a two-dimensional t-SNE embedding of the data set using parameter values metric=cosine, perplexity=30, exaggeration=2, excluding the target variable from the embedding construction. We then explain the resulting embedding using VECA using the original input variables. The top four contrastive explanations and the top four descriptive explanations are shown in Fig.~\ref{fig:wine_explanations}.

Figs.~\ref{fig:wine_explanations}.a and \ref{fig:wine_explanations}.b reveal that different values of the \textit{Wine Type} and \textit{Chlorides} variables appear in distinct regions of the embedding, while the variables \textit{Total Sulfur Oxide} and \textit{Residual sugar} in Figs.~\ref{fig:wine_explanations}.c and \ref{fig:wine_explanations}.d exhibit a small degree of overlap. Fig.~\ref{fig:wine_explanations}.a indicates that the two types of wines are clearly separated from one another in the embedding. This variable was not used to construct the embedding, indicating substantial differences between the underlying chemical properties of red and white wines. However, we identify a small cluster between the two large groups of wine that is only partially included in the orange region, and its neighboring samples do not appear to belong to either red nor white wine. We inspect the underlying samples for each wine type in Fig.~\ref{fig:wine_separation}. The plot reveals that most white and red wines are indeed contained within the two regions, with minimal mixing between red and white wines. The plot also shows that this in-between cluster is somewhat mixed, indicating a small group of red and white wines with similar chemical properties.

\begin{figure}[ht]
  \centering
  \includegraphics[width=\linewidth]{wine_type_separation.pdf}
  \caption{We plot each region from Fig.~\ref{fig:wine_explanations}. (a) highlights the points corresponding to red wine, while (b) highlights the points corresponding to white wine. We see that there is minimal mixing between the two wine types. We also observe that the small in-between cluster contains a rough mix of 50\% white wines and 50\% red wines.}
  \label{fig:wine_separation}
\end{figure}

Descriptive visual explanations can also lead to the discovery of correlations between explanatory variables. For instance, the blue region on the left-hand side of Fig.~\ref{fig:wine_explanations}.e is comprised of three explanatory variables: \textit{wine type = 'red'}, \textit{total sulfur dioxide < 60.13}, and \textit{0.06 < chlorides < 0.13}. We can thus conclude that red wines generally contain lower levels of \textit{total sulfur dioxide} than white wines and that their levels of \textit{chlorides} generally fall between 0.06 and 0.13. We can consult the contrastive explanations to determine whether these levels of \textit{chlorides} are high or low. Inspecting Fig.~\ref{fig:wine_separation}.b, we can conclude that this is a middle-range value of chlorides.

We next demonstrate that discretization alone can be helpful in the visualization of feature values, especially in the presence of outlier values.
A common approach for explaining embeddings in terms of a particular input feature is to color-code each point in the scatter plot based on its feature value. However, this approach is sensitive to outliers that distort the color scale, resulting in a highly skewed point-color distribution.
For instance, Fig.~\ref{fig:wine_discretization}.a shows the distribution of the values of the \textit{Residual Sugar} variable. Notice that the histogram is skewed to the left due to a small number of extremely high values. Consequently, the resulting scatterplot does not provide much useful information, as the points appear more-or-less colored in the same way. A common remedy to this problem is to log-transform the values. However, this is not always effective and increases the cognitive load on the analyst, as now they must think about variable values in terms of their log scale. Fig.~\ref{fig:wine_discretization}.b shows the log-transformed values of the original \textit{Residual Sugar} input variable.

\begin{figure}[ht!]
  \centering
  \includegraphics[width=\linewidth]{wine_discretization.pdf}
  \caption{We compare our approach to the typical approach to explaining embedding with the original input variables using scatter-plot color-coding. We use the \textit{Residual Sugar} variable from the wine quality data set~\cite{Cortez2009} as an example. (a) shows a typical color-coding scheme, where the color scale is skewed as a result of a few outliers. Consequently, the plot is not informative. We apply a log-transform to fix this issue in (b), but this now requires reasoning about the values in log-scale. (c) show our discretization proceedure without any data transformations. Due to discretizaiton, the visualization does not suffer from this problem, while the final discretization in (d) additionally merges variable values into three bins corresponding to `low', `medium', and `high` concentrations of `Residual Sugar'.}
  \label{fig:wine_discretization}
\end{figure}

Applying our discretization approach mitigates this problem. Fig.~\ref{fig:wine_discretization}.c shows that discretization limits the effects of outliers. These often get put into one bin and have a minimal negative effect on the colors in the resulting scatterplot. Notice that the scatterplot in Fig.~\ref{fig:wine_discretization}.c looks similar to that in Fig.~\ref{fig:wine_discretization}.b. However, we can still reason about the variable values in terms of their original scales. Applying our merging procedure merges spatially overlapping bins, resulting in a cleaner overall visualization. The scatter plot in Fig.~\ref{fig:wine_discretization}.d shows three distinct bins, where the right-hand side of the scatter plot seems to be characterized by higher values of \textit{Residual Sugar}, which transition to lower values as we move to the left-hand side. Notice that the outlier values were all correctly bundled with the higher values.

\subsection{Forest Cover Type}

We here adopt a similar evaluation strategy as Sohns et al.~\cite{Sohns2022}, as it nicely illustrates how visual explanations can be used to aid in the interpretation of deep models and uncover the inferred relationships between the input and target variables.

The forest cover type data set~\cite{Blackard1999} contains 581,012 samples described by cartographic variables including elevation, aspect, and distance to roadways. The dataset is primarily used in supervised learning settings, where the aim is to distinguish between seven forest cover types.
As in the previous two examples, we generate a two-dimensional t-SNE embedding of the full data set using parameter values metric=cosine, perplexity=500, and exaggeration=4. We then explain the resulting embedding using VECA in terms of the original data features and show the top four contrastive explanations in Fig.~\ref{fig:covertype_explantions}.

\begin{figure}[htb]
  \centering
  \includegraphics[width=\linewidth]{covertype_contrastive.pdf}
  \caption{Forest cover type contrastive explanations}
  \label{fig:covertype_explantions}
\end{figure}

The contrastive layouts in Fig.~\ref{fig:covertype_explantions} reveal that \textit{Wilderness Area}, i.e., the national park where the samples are located, is the primary variable driving cluster formation in the embedding space. This indicates that the composition of trees in different areas of a particular national park is more similar than the composition of trees between areas in different national parks. This may be undesirable if, for instance, our ultimate goal is to apply our model to other national parks.

As the goal with this data set is the prediction of the forest cover type, it is encouraging to see that the \textit{Cover Type} variable appears to be somewhat localized in the embedding space, as shown in Fig.~\ref{fig:covertype_explantions}.d. The plot reveals two distinct groups of forest cover types, the orange group corresponding to \textit{Cottonwood/Willow}, \textit{Douglas-Fir}, and \textit{Ponderosa Pine} cover types and the blue group to the remaining four cover types. This localization indicates that machine learning models will likely have little difficulty separating samples between these two groups of cover types. For instance, Fig.~\ref{fig:covertype_explantions}.b suggests that we could separate the orange cover types from the blue cover types fairly well based only on the \textit{Elevation} variable alone.
While Fig.~\ref{fig:covertype_explantions}.d indicates mixing between the forest cover types contained within the orange and blue regions, this does not necessarily mean machine learning models will struggle to differentiate between the different cover types.
The embedding in Fig.~\ref{fig:covertype_explantions} was constructed in an unsupervised way using the t-SNE algorithm, which positions similar samples close to one another. In this case, the similarities between data points were computed using all available features. However, in a supervised setting, the model may determine that some input variables do not relate to the prediction task and may ignore them altogether. Omitting these features from the embedding construction process would produce a different embedding, which may better separate the different forest cover types.

To illustrate this point, we fit a four-layer neural network with two hidden layers (with dimensions 256 and 128) using ReLU activation units. We use the same data split as in the original publication~\cite{Blackard1999}. We optimize the model using the Adam optimizer for 2,000 epochs. Our final model achieves $\sim50\%$ predictive accuracy, lower than the $\sim70\%$ reported by Blackard and Dean~\cite{Blackard1999}.
We note that our goal here is not to fit the most precise predictive model but to demonstrate how VECA can be used to aid in model debugging and interpretation.
To better understand what our trained deep-learning model is doing, we extract the latent embeddings of all the data points and generate a two-dimensional t-SNE embedding using the same parameters as before. We then use VECA to explain this embedding in terms of the original data features.

%to gain a better understanding of the types of relations deep-learning models learn, and what kind of mistakes they are likely to make.

%A common use of two-dimensional embeddings is model interpretation. This is particularly useful in deep learning, where we can examine a two-dimensional representation of the learned latent embeddings and inspect whether the model has learned to differentiate between the classes of interest. In deep models, the mapping between the learned latent embeddings and the original input variables is often too complex to reason about directly. However, inspecting a two-dimensional visualization of the learned embeddings can still make sense as these can shed light on the types of relationships between input variables that the deep-learning model learned and which input variables might be important for the overall prediction.

Ideally, the two-dimensional embedding would reveal seven distinct clusters, each corresponding to a distinct forest cover type. This would indicate a perfect separation between the different classes. However, achieving this level of separation in most real-world data sets is rare. Fig.~\ref{fig:covertype_model}.a shows the resulting t-SNE embedding. The plot depicts an elongated structure containing all the data points with no clear clusters. However, the visual explanation corresponding to the \textit{Cover Type} variable in Fig.~\ref{fig:covertype_model}.f shows that even though the model could not establish clear boundaries between the different forest cover types, it has learned to differentiate between some groups of cover types. For instance, the orange region corresponding to Cottonwood/Willows, Douglas Firs, and Ponderosa Pines is located on the opposite side of the embedding than the green region associated with the Krummholz cover type. This indicates that our model should be able to distinguish samples between these two classes. On the other hand, the overlap between the green and red regions associated with Krummholz and Spruce/Fir cover types suggests that the model may have difficulty differentiating between these categories. The confusion matrix in Fig.~\ref{fig:covertype_model}.b confirms both of these hypotheses: our model can distinguish between Krummholz samples and Cottonwood/Willows, Douglas Firs, and Ponderosa Pines samples with perfect accuracy, but misclassifies some samples with Krummholz cover type as Spruce/Fir cover types.

\begin{figure}[thb]
  \centering
  \includegraphics[width=\linewidth]{covertype_model.pdf}
  \caption{Forest cover type model. The abbreviated class names in the confusion matrix correspond to Cottonwood/Willow (CW), Douglas-Fir (DF), Ponderosa Pine (PP), Aspen (AS), Lodgepole Pine (LP), Spruce/Fir (SF), and Krummholz (KR).}
  \label{fig:covertype_model}
\end{figure}

VECA can also be used to aid in model interpretation and provide hints into the types of variable relationships that deep-learning models may be infering. While it is possible to directly inspect the model's weights and determine the feature relationships and importances through specialized explanatory techniques, visual explanations offer an alternative way to gain a sense of what is happening under the hood. We generate contrastive layouts to the t-SNE plot of the latent embeddings and show the top-four layouts in Figs.~\ref{fig:covertype_model}.c-f.

The contrastive visual explanations in Figs.~\ref{fig:covertype_model}.c, \ref{fig:covertype_model}.d, and \ref{fig:covertype_model}.f suggest that the model may have learned a relationship between specific soil types, high elevations, and the Krummholz forest cover type. Fig.~\ref{fig:covertype_model}.e shows that the wilderness area variable, i.e., the geographic location from which each sample was collected, also explains some aspects of the latent embedding. This spatial correlation could indicate overfitting if, for instance, our goal was to develop a model that could classify forest cover type regardless of geographic location. Conversely, if our goal was to classify only samples from these four geographic areas, relying on the geographic location may be a desirable property as forest cover types are likely to differ between national parks.

In Fig.~\ref{fig:covertype_explantions}, VECA identified the \textit{Hillshade 3pm} variable as one of the most informative contrastive variables for explaining that particular embedding. However, its absence from Fig.~\ref{fig:covertype_model} suggests this variable was not as important for the prediction of forest cover type. On the other hand, the \textit{Soil Type} variable appears at least somewhat useful for the prediction task, while it was not as important for explaining the original embedding.

We warn that these visual explanations should not be viewed as definitive, and one should only use them to generate hypotheses that require further investigation. When embedding a high-dimensional data set into two dimensions, distortions will inevitably be introduced in the resulting visualization, and we should view the relationships between data points should subsequently with a healthy degree of skepticism. However, a spatial correlation in the embedding space suggests that the model has assigned some value to that particular feature and has learned some relationship between the input variable and the target class. Otherwise, the variable would likely be fairly decorrelated with the embedding space. In summary, visual explanations can serve as a good starting point in interpreting deep models, but additional analysis and validation are necessary to confirm any initial hypotheses.

\section{Discussion and Future Work}

The region construction step of approach could be replaced by alpha-hulls from Sohns et al.~\cite{Sohns2022} or any other one of the embedding enrichment schemes outlined by Nonato and Aupetit~\cite{Nonato2018}. Alpha-hulls may even benefit in terms of purity. However, this could be problematic if the users chooses to insert new data points into existing embeddings. Modern implementations of t-SNE~\cite{Policar2019} and UMAP~\cite{McInnes2018} both enable users to insert out-of-sample data points into existing embeddings, and the tight boundary of alpha hulls might leave some points outside of the ecompassed region.

Using kernel density estimates to extract regions can also miss smaller clusters of data points. Due to the nature of kernel density estimation, and our choice to extract regions at a prespecified contour level, some small clusters could easily be missed, even if they are compeltely enriched with a single variable value, simply because there are not enough data points in the cluster. Developing alternative techniques for region estimation is a good avenue for future work.

Our approach achieves scalability in the number of data points through sampling. By default, we limit the number of data points to 5,000 and use those to estimate regions and contruct visual explanations. Our approach works quite well even when this number is increased to e.g. 10,000, but the results are largely the same. Our approach is generally not limited by the number of data points, but rather, the number of different variables. For each variable, we perform several computatiation intesive tasks. We first apply K-Means discretization to each variable, then perform kernel density estimates for each variable. We then determine the number of sample data points that fall within each region . Finally, each region undergoes an iterative post-hoc iterative merging process which primarily depends on the number of discretization bins or the number of different categories in the categorical variables. Data sets containing thousands to tens of thousands have become widespread in fields such as bioinformatics, where non-linear dimensionality reduciton methods are routinely used to inspect transcriptomics data. Developing more scalable methods capable of generating visual explanations for data sets containing thousands of variables would be of great interest.

While the focus of our VECA is to create a fully-automated pipeline for generating visual explanations of embeddings, one can easily envision an interactive system where these kinds of visual explanations could be explored in more detail by the user. For instance, a user presented with a descriptive explanation such as the one in Fig.~\ref{fig:wine_explanations}.e may discover the blue region corresponds to red wine, low levels of sulfur dioxide, and certain levels of chlorides. However, they may then wonder where in the plot high levels sulfur dioxide appear, in which case the user would be presented with a contrastive explanation of this variable as in Fig.~\ref{fig:wine_explanations}.c. The user may similarily wonder where exactly the three regions contained within the blue region occur, and may wish to inspect the subregions, as seen in Figs.~\ref{fig:covertype_model}.c-f. Alternatively, the user may also be intersted in the purity of the region, and may wish to inspect a plot that highlights exactly which data samples exhibit the particular explanatory variable, and which such samples are missing from the regions, similar to what is shown in Fig.~\ref{fig:wine_separation}. Such a user interface could seamlessly be incorporated into existing visual analytics tools such as Orange~\cite{Demsar2013}.

\section{Conclusion}

This paper presents VECA, a visual explanation framework designed to automatically generate visual explanations for two-dimensional embeddings. Explanations are generated in terms of any variables of choice, most commonly, the input variables used to generate the embedding. VECA is able to generate two types of visual explanations: contrastive explanations, which aim to find the most informative input variables, and descriptive variables, which aim to describe as much of the space as possible using different variables or combinations of variables.
Our approach involves a novel discretization scheme based on the spatial proximities between different discretization bins in the embedding. VECA generates multiple possible visual explanations. In contrastive explanations, we develop a novel visual explanation ranking scheme, preferring layouts with little overlap that are as informative as possible. For descriptive explanations, we frame the explanation construction process as a graph-independent set problem and develop a novel ranking scheme that prefers diverse and informative visual explanations.
We demonstrate the utility of our approach on three data sets of increasing complexity. We also demonstrate how VECA can be used to gain an understanding into deep networks, uncover the types of errors these methods are likely to make, and what kinds of relationships they are likely to have learned.

We also release our reference Python implementation of VECA. VECA is available on GitHub and can be installed via PyPI. VECA is easy to use, and we have worked hard to make the parameters easy to understand. 

Overall, our work contributes to the growing field of interpretable machine learning and offers a new perspective on how to explain non-linear embeddings in terms of their original features. It also provides a new exploratory method for describing the behavior of deep neural network models.

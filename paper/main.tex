%% Abstract section.
\abstract{%
Two-dimensional embeddings resulting from dimensionality reduction techniques, such as t-SNE, UMAP, and multidimensional scaling, are widely used in various scientific fields to visualize high-dimensional data. These visualizations provide a useful tool for exploratory data analysis, allowing researchers to identify clusters, outliers, and other interesting patterns in the data. However, interpreting the resulting visualizations can be challenging, as it often requires additional analysis to understand the differences between data points in different regions of the embedding space. To address this issue, we propose VECA (Visual Explanations and Contrastive Analysis), an automatic embedding-annotation approach that generates visual explanations for any two-dimensional embedding. Motivated by insights from social science, VECA is designed to produce informative and contrastive explanations that best characterize distinct regions in the visualization compared to the remainder of the embedding space. Unlike existing approaches, VECA automatically performs both the identification and selection of possible visual explanations according to their information content and contrastive importance, then generates a small but diverse set of informative explanations. We demonstrate the utility of VECA on several high-dimensional datasets, including transcriptomics data.

Our open-source, Python implementation of VECA is freely-available at \url{https://github.com/pavlin-policar/veca}.
}

\section{Visual Explanations}

In this section, we develop a conceptual framework for the generation and selection of visual explanations.
Given a data set $D$ and an embedding $Y$, our goal is to generate sets of visual explanations that convey some information about the structure of the embedding. For instance, if there is an apparent cluster in the embedding, what features differentiate it from the remaining data points.
The data set $D$ can contain both continuous and discrete features. To be able to apply the same treatment to both types of variables, we expand each feature into a collection of \textit{explanatory variables}. An explanatory variable is a binary indicator variable which indicates whether the particular sample has a particular value or range of values. For example, we generate one explanatory variable for each distinct category in a discrete variable. Samples corresponding to that particular feature value are assigned a value of one and zero otherwise. This is simply one-hot encoding. For continuous variables, we apply a similar approach preceeded by discretization.
Each explanatory variable is associated with a \textit{region} $r$, which represents collections of spatially localized points in the embedding space enriched for that paritcular explanatroy variable.
Finally, we define a \textit{visual explanation} as a collection of regions or, equivalently, explanatory variables, that conveys some useful information to the end-user about the structure of the embedding.

Our conceptual framework can be split into three distinct phases: (i) region construction, (ii) explanation construction, and (iii) explanation selection. We next describe each of these phases in detail.

\subsection{Region construction}

A region typically corresponds to one or more polygons in the embedding space, each encompassing a set of data points having some particular feature value or range of values.
This implies that the data points falling outside of the region do not belong to the this same category.
Ideally, a region would contain all data points with that feature value and exclude all others.
However, it is easy to see that an optimal solution according to this criteria would lead to overfragmented, complex polygons, which would be difficult to interpret and provide little benefit to the end user.
Instead, we want to generate easily-understandable and visually-appealing regions, which may not encompass \textit{all} data points perfectly, but would prefer for them to be \textit{generally} accurate.

Several approaches for generating regions that fit this description. For instance, Sohns et al.~\cite{Sohns2022} propose rangesets, which produce collections of alpha-hulls for each input variable. We could also represent regions as density maps using contour plots, as proposed by Li et al.~\cite{Li2022}. In our approach, we opt to use a simple approach based on extracting contours from kernel density estimates.

\subsection{Explanation construction}

Once we have extracted regions for each of our derived explanatory variables, we would like to show these to the user in an information-rich manner. While we could show individual explanatory variables to the user, this would likely overwhelm the user with a large number of plots. Probably, we want to avoid explanations that are too cluttered i.e., contain too many regions, or, the regions overlap too much. This makes the plot unwieldly and takes a lot of cognitive effort to understand anything from this plot. Intuitively, we want to generate visual explanations that are visually appealing, contain regions that do not or minimally overlap.

\subsection{Explanation selection}

We aim to generate visually appealing, minimally-overlapping collections of regions.
While the explanation construction process can produce a large number of potential visual explanations, many of these explanations may not be particuarily useful. Additionally, we wish to avoid overwhelming the user with too many visual explanations.
At the very least, we need a mechanism for ranking visual explanations in some sensible way.
At this point, we must think about the goal of our visual explanation, i.e., what kind of information are we trying to convey to the user, as this will dictate what kinds of visual explanations will be selected, and which ones will be ranked at the top.

We here consider two types of visual explanations: contrastive and descriptive explanations.

For contrastive explantaions, we tend to use fewer explanations than if we were asked a "describe this robot" question. (describe this robot, vs, what are the differences between these two robots). Same survey paper (the long one).

We define a \textit{contrastive visual explanation} is a visual explanation, where the contained regions contain all the different possible variable values of a single variable in the original dataset.
In terms of explicitly stating the foil, the foil here would be \textit{``Where do the different feature values occur?''}

We define a \textit{descriptive visual explanation} is a visual explanation, where the contained regions contain all the different possible variable values of a single variable in the original dataset.
In terms of explicitly stating the foil, the foil here would be \textit{``what makes this cluster unique? Why is this cluster unique? Because it has this feature. The foil? Why are the other samples not in this cluster?''}


\section{Methods}

In the previous section, we laid out the conceptual framework for visual explanations. In this section, we describe \textit{Visual Explanations and Contrastive Analaysis (VECA)}, our fully-automated approach for generating visual explantations for arbitrary two-dimensional embeddings.

\subsection{Region construction}

Our region construction approach is comprised of extracting contours from a kernel density estimate. We construct regions in the following way. First, we extract all potential explanatory variables from the input data. These can correspond to specific values, sets of values, or ranges of values. The goal is to derive explanatory features that can be useful in understanding the different spatial regions of the embedding. Next, using these explanatory variables, we generate explanatory regions, represented by collections of polygons, which correspond to spatial regions in the space that are enriched with a particular explanatory variable. Our approach can produce overfragmented regions, so a post-hoc merging proceedure is applied. This both reduces the number of possible explanatory regions and improves visual coherence by merging highly-overlapping regions. We describe each of these step in detail.

\subsubsection{Extracting explanatory variables}

The input data set can contain both discrete and continuous variables. Since we want to explain the embedding in terms of the different values or ranges of values of the input variables, we expand each input variable into a collection of explanatory variables. For continuous variables, we use $K$-Means quantization to split the values into $K$ discrete intervals. By default, we split into 5 bins, corresponding to the typical five-point scale: ``very low'', ``low'', ``medium'', ``high'', and ``very high''. Dicrete varaibles are one-hot encoded, resulting in $K$ different explanatory indicator variables, each corresponding to a particular categorical value of the input variable.

\subsubsection{Extracting explanatory regions}
\label{sec:kde_estimation}

After extracting explanatory variables, we determine the regions of the space where these explanatory variables are enriched.

The first step in our approach is to identify the scale of the embedding. Different embedding algorithms produce different embeddings that can span different scales, e.g., one embedding may span from -5 to 5 along its dimensions, while another may span from from -50 to 50. Additionally, using the same scale may not make sense for data sets of different sizes. For instance, in a dataset with 50 samples, we are likely to be interested in groups of 10-20 points, while in a dataset containing 2 million samples, these small groups will be of less interest and could be a result of noise. To determine the scale $\sigma$ of each embedding, we first determine the scale of the groups we are interested in. We select $k=\sqrt{N}$, as this is commonly used in KNN classification. We then compute the median distance of each points's $k$-th nearest neighbor and use that as the scale of the embedding.

Next, for each binary explanatory variable, we obtain its kernel density estimate $D$ using a Gaussian kernel with bandwidth $\sigma$. Next, we extract the contours of the density estimate at a user-defined level, typically at $0.25 \cdot \max D$. Note that because the density estimate may be multimodal, e.g., if an explantory variable is enriched in different regions of the space, we may obtain more than one contour. These contours represent the regions which we use in subsequent steps of our analysis and correspond to spatial regions of the space in which each particular explanatory variable is enriched.

\subsubsection{Post-hoc explanatory variable merging}
\label{sec:merge_overfragmented}

It is unlikely that five bins will always correspond to a reasonable discretization of any particular variable. It is also unlikely that one single parameter value $k$ will be optimal for all variables, and this can often lead to overfragmentation, resulting in a large number of fragmented regions. To remedy this, we apply post-hoc merging which merges bins with a high degree of overlap.

For ordinal and continuous variables, we only allow merging neighboring bins, e.g, the discretized bins $\{ x < 5, 5 \leq x < 6, 6 \leq x\}$ could be merged into $\{x < 6, 6 \leq x\}$, but not into $\{ 5 \leq x < 6, x < 5 \mid x \geq 6\}$.

For categorical variables, we apply one-hot encoding, and use the same variable merging scheme as before. For ordinal categorical variables we apply the same merging restriction as before, merging only adjacent bins. E.g, the ordinal values $\{1, 2, 3, 4\}$ could be merged into $\{\{1, 2, 3\}, \{4\}\}$, but not into $\{\{1, 4\}, \{2, 3\}\}$. For nominal categorical variables, we apply no such restriction. E.g., the categorical variable values $\{red, green, blue\}$ could be merged into $\{\{red, green\}, \{blue\}\}$.

More concretely, to merge two explanatory variables, by default we require that their sample overlap is at least 50\%. 
\begin{equation}
\text{overlap}(r_1, r_2) = |r_1 \cap r_2| \notag
\end{equation}
where $r_1$ and $r_2$ are the regions in question, and $|r_1 \cap r_2|$ denotes the cardinality of their intersection.
We also require that the merged region improves the overall purity of the regions by at least 5\%. The purity of a region is defined as
\begin{equation}
\text{purity}(r) = \frac{1}{|r|} \sum_{i \in r} x_i \notag
\end{equation}
where $r$ is the region of interest, $|r|$ is the number of points contained withing the region, and $x_i$ is the binary explanatory variable value.
That their spatial localization is not decreased. We measure spatial localization using Geary's C spatial autocorrelation index, defined as
\begin{equation}
C=\frac{N-1}{2 \sum_{ij} W } \frac{\sum_i \sum_j w_{i j}\left(x_i-x_j\right)^2}{\sum_i\left(x_i-\bar{x}\right)^2},\notag
\end{equation}
where $N$ is the number of data samples, $W$ is a weighted adjacency matrix indicating the spatial proximities between data points, and $x_i$ is the feature value of sample $i$.
To compute the adjacency matrix $W$, we utilize the scale $\sigma$ computed in Sec.~\ref{sec:kde_estimation}. For each point we find all its neighbors that are at distance at most $3 \cdot \sigma$. We then compute the probability density function of each of these neigbhors using a Gaussian distribution centred at each point using bandwidth $\sigma$.

As merging the regions produce new, generally, larger regions, it may well happen that after one round of merging, that new potential regions may overlap sufficiently to be merged. We perform this merging proceedure iteratively until no further merges can be performed.

If no particular variable value is localized to a specific region of the embedding space, our merging proceedure could merge all the explanatory variables for a variable, leaving a single region encompassing the entire space. This is desirable, as this indicates that this particular variable holds no bearing when trying to explain the embedding, and is discarded from future consideration for generating visual explanations.

An example of the overfragmentation and the subsequent merging proceedure is shown in Fig.~\ref{fig:overfragmentation}).

\subsection{Contrastive explanations}

Contrastive explanations of features aim to show where in the embedding different feature values occur.

\subsubsection{Explanation construction}

Generating contrastive explanations is straightforward: for each input variable, we simply include all its derived explanatory variables. While the different regions may overlap to some degree, our explanatory variable merging proceedure ensures that regions with significant overlap are merged beforehand.

\subsubsection{Explanation selection}

The construction proceedure provides a collection of possible contrastive explanations, one for each input variable. However, some explanations may be more informative than others.
Intuitively, a variable whose values are localized in disjoint regions of the space will be the most informative will be easier to reason about than a variable whose values are distributed more evenly.

To adhere to the principle of ``simple explanations'', we aim to present the user with as few plots as possible. We achieve this by trying to merge regions with sufficient overlap and bipartite mapping between pairs of variables where the edges in the graph are created when there is sufficient overlap between the two regions. By default we require an overlap of at least 95\% of samples in both regions. This can also by used as a visual proxy for identifying feature correlations, in some cases, even non-linear ones.

We want the number of explanatory regions to be manageable. For instance, one region is not particularily informative, while 10 is just too much clutter. We do the Gaussian log-probability.


\subsection{Descriptive Explanations}

With descriptive explanations, we aim to show interesting combinations of explanatory variables such that the resulting plots are as informative as possible. This can include interesting combinations of input variables, and can lead us to uncover interesting relationships between specific variable values.

\subsubsection{Explanation construction}

In descriptive explanations, we are no longer limited to showing explanatory variables from a single input variable, but are free to choose any combination of explanatory variables from any input variable.
It is common that several explanatory variables appear in similar regions of space. For instance, if Fig.~\ref{fig:bipartite_matching}, the three input variables \textit{petal length}, \textit{petal width}, and \textit{species} are highly correlated, and occupy roughly the same regions of the space. To reduce the number of possible visual explanations, we merge together these into a single visual explanation. We only do this when there is sufficient overlap between all pairs of regions. By default, we require that at least 90\% of the encompassed samples are shared between any two pairs of merged regions. Note that the samples need not necessarily have that particular feature value, it only needs to be encompassed by the region.
We also require that the resulting merged cluster has a purity of at least 50\%, i.e., at least 50\% of all samples encompassed within this new region have at least one of the merged variables.
As an additional requirement, we require that each of the resulting clusters has a Geary's C index of at most 0.5. Note that this step is different from the merging proceedure described in Sec.~\ref{sec:merge_overfragmented}, as we do not limit ourselves to merging adjacent bins, or even explanatory variables derived from the same input variable.

\begin{figure}[thb]
  \centering
  \includegraphics[width=\linewidth]{iris-bipartite-matching}
  \caption{The plots in panels (a) (b), and (c) correspond to contrastive explanations for three different variables in the Iris data set. The variables represent \textit{petal length}, \textit{petal width}, and \textit{iris species}, respectively. Notice that each of these three plots contain regions that occupy the same regions of the space. For instance, we would lose almost no information if the regions corresponding to \textit{petal length < 2.46}, \textit{petal width < 0.67}, and \textit{species = `iris setosa'} were merged into a single region. A similar mapping can be found between the other two subregions in each of the three variables.   \label{fig:bipartite_matching}
\end{figure}

Having merged overlapping explanatory variables, we next need to find combinations of these resulting regions so that they produce informative visual explanations.
To avoid cluttering the plot, we want to include variables in each visual explanation so that we have as little overlap as possible. We achieve this by casting this as an graph-independent set problem. We first compute the overlap graph between all explanatory variables, placing an edge between explanatory variables if the overlap between regions exceeds the maximum user-specified threshold, by default 20\% of overlapping samples. Then, the independent sets of this graph are the  find combinations of non-overlapping explanatory variables which do not exceed this prespecified threshold.

\subsubsection{Explanation selection}

Unlike contrastive explanations, descriptive explanations are not limited to including only explanatory regions for a single variable. We instead want to find a combination of explanatory regions, perhaps from different variables, that are as informative as possible. What "informative as possible" means will be defined later on.

Once we have generated the explanatory regions for the relevant variables, we need to rank them according to their importance and informativeness. In order to do this, we take several factors into consideration.
Firstly, we prioritize simple explanations over complex ones. We defined the term ``simplicity'' to mean that it is easily understandable by any end user. Practically, this means preferring explanations containing between 2-5 minimally-overlapping explanatory variables which are highly localized in distinct regions of the space. Additionally, we prefer explanations which cover as much of the embedding as possible.

We achieve this by calculating a score for each embedding layout by considering the following factors. To minimize overlap between regions, we compute the sample overlap between all pairs of regions. To prefer simpler, non-fragmented regions, we calculate the number of polygons each explanatory region contains, and calculate the overall polygon to region ratio for each visual explanation. We prefer explanations where this ratio is closer to one, as this indicates that each explanatory variable has one associated polygon. To maximize embedding coverage, we compute the percentage of total points in the embedding contained within any single region in the visual explanation. To bias explanatrions a smaller number of explanatory variables e.g., between 2-5, we impose a Gaussian prior with $\mu=3$ and $\sigma^2=2$. We then evaluate the probability density function at the number of contained variables in the visual explanations. Intuitively, a higher value will be assigned when the visual explanation contains 3 explanatory variables than when it contains 2 explanatory variables.

Another factor to consider is explanation diversity. Unlike in contrastive explanations, where each subsequent explanation is completely different from one another, and the user is exposed to completely different explanatory variables with each visual explanation, visual explanations can be repeated as often as possible in descriptive explanations. However, intuitively, if a user has seen a particular explanatory variable in the first plot, it would be more informative for the next several visual explanations to not contain this explanatory variable, and prefer explanatory variables that the user has not yet seen.

To achieve this diversity in visual explanations, we develop an iterative visual explanation selection technique. In addition to the layout scores, which can be computed independently for each layout separately, we introduce an explanatory variable penalty which is applied to each visual explanation. Importantly, this penalty depends on the previously selected visual explanations, and consecutive visual explanations which contain repeating visual explanations are heavily penalized. As we don't want explanatory variables to be shown only once, we just want them not to appear in two or three plots in a row, we apply an exponential decay to this variable penalty, such that a variable is no longer penalized after e.g. three visual explanations. This approach enforces diversity in the produced visual explanations and prevents explanatory variables to be repeated too frequently in the visual explanations. Thus, the user can get a better sense of different regions of different explanatory variables while looking at a small number of visual explanations.

\section{Case studies}

In the following, we present three case studies of increasing complexity. We being by running through our analysis on the simple Iris flowers data set~\cite{Anderson1936} which is well-known and easy to understand. We continue with the Wine Quality data set~\cite{Cortez2009}, which contains more input variables, and requires more explanation. We conclude by applying our approach on the large Forest Covertype data set~\cite{Blackard1999}, containing over half a million data points, and demonstrate how VECA can be used to gain insight into what kinds of errors predictive models may make, and also to understand what kinds of relationships between variables deep-learning models may be learning.

We use default parameter settings in the VECA Python library unless stated otherwise.

\subsection{Iris Flowers}

We walk through the different steps of our analysis on the Iris data set from Anderson~\cite{Anderson1936}. This small data set profiles 150 iris flowers with four continuous variables containing pyhsical measurements of individual flowers (sepal length, sepal width, petal length, petal width) and provides a classification of their species (Iris Setosa, Iris Versicolor, Iris Virginica).

We first construct a two-dimensional t-SNE embedding of the data set with parameter values metric=cosine, perplexity=30 using the \textsf{openTSNE} library~\cite{Policar2019}. We then explain the resulting embedding using VECA. For this example only, we perform discretization into three bins instead of five, as this feature setting better demonstrates the types of problems one must take into consideration when performing variable merging. The steps involved in the pipeline are outlined in Fig.~\ref{fig:iris_pipeline}.

\begin{figure*}[tb]
  \centering
  \includegraphics[width=\textwidth]{iris_pipeline.pdf}
  \caption{We illustrate the region construction process on the Iris data set.}
  \label{fig:iris_pipeline}
\end{figure*}

The top row of Fig.~\ref{fig:iris_pipeline} shows a standard approach to explaining embeddings in terms of their original features. The points in the scatter plot are colored according to their feature values. This approach works well for a small number of input features, but quickly grows unwieldly as the number of input features increases. Additionally, the plots are typically ordered according to the original variable order, making it difficult to reason about correlted variables in the embedding space. Finally, the colors correspond to different feature values. How good this is is determined by the color palette used. In general, it is fairly easy to see low and high values of the feature, e.g., the first two panels in the top row of Fig.~\ref{fig:iris_pipeline} show a clear distinction between the left-hand and the right-hand side of the plot in terms of feature values. However, it is difficult to discern anything other than ``low'' and ``high'' values. The right-most panel in the top row of Fig.~\ref{fig:iris_pipeline} shows the categorical target variable. While this plot is very clear, these kinds of plots become increasingly difficult to interpret and become increasingly cluttered as the number of categories increases.

The second row of Fig.~\ref{fig:iris_pipeline} shows the initial explanatory variables for each input variable, grouped by input variable. Notice that the third and fourth panels contain regions that contain a high degree of overlap. For instance, in the third panel, the orange region corresponding to the derived feature \textit{sepal length (cm) > 6.55} overlaps almost entirely with the green region corresponding to \textit{5.53 < sepal length (cm) < 6.55}. These two discretizations could easily be merged into a single discrete interval \textit{sepal length (cm) > 5.53} to unclutter the visualization without much loss of information. Indeed, this is exactly what happens in the next step of the VECA pipeline in the third row of Fig.~\ref{fig:iris_pipeline}, where our post-hoc merging proceedure merges the above mentioned explanatory variables.

The fourth panel in the second row of Fig.~\ref{fig:iris_pipeline} demonstrates a more complex scenario. The blue region corresponding to \textit{sepal width (cm) < 2.85} is localized to the right cluster, and the green region corresponding to \textit{sepal width (cm) > 3.44} is localized to the left cluster. However, the intermediate values contained within the orange region corresponding to 
\textit{2.85 < sepal width (cm) < 3.44} are present throughout the embedding. We may consider merging the orange region with the green region, producing an explanatory variable corresponding to \textit{sepal width (cm) > 2.85}, however, this may mislead users to think there are only two groups of feature values, with high values distributed along the entire embedding, and low values appearing only in the right-hand cluster. Alternatively, we may instead opt to merge the \textit{sepal width (cm) < 2.85} and \textit{2.85 < sepal width (cm) < 3.44} regions, but this may lead to similar confusion. Alternatively, we may choose to leave the regions as they are, but this may mistakenly give the user the mistaken impression that the left-hand cluster contains only high values of \textit{sepal width (cm)} if they are shown only that single explanatory region. Leaving the regions unmerged would also result in cluttered visualizations. In VECA, we merge all three clusters into a single explanatory variable. This means that the entire variable is described by a single region which encompasses the entire space, and is discarded from any explanations. Other approaches may be possible, but we feel it is better to remove unclear visual explanations than to provide misleading explanations.

The third row of Fig.~\ref{fig:iris_pipeline} shows the explanatory variables after the merging proceedure. Notice that the first, second, and last panels remain the same as in the row above, because the initially proposed regions do not really overlap. The explanatory variables in the third panel were merged into two explanatory variables, while the fourth panel shows an explanatory variable that was merged into one, and will be discareded from future analysis. Note that this variable may have been merged in a different way if a different number of bins was chosen. For instance, if we had chosen five bins, as is the default in VECA, perhaps the orange region would have been further split into a left and right region, and the resulting merged region may have been similar to the one shown in the third panel.

The last row of Fig.~\ref{fig:iris_pipeline} shows all the generated contrastive and explanatory explanations of this embedding. Notice that the first panel in the contrastive explanations display three variables. This is possible as the three variables all contain regions which occupy the same regions of the space. It is evident from the visual explanations that it would be easy to correctly classify iris flowers by species. We would only need to look at petal width and petal length and obtain a high degree of accuracy. As this data set is fairly straightforward, the descriptive explanations do not really reveal anything that the contrastive explanations don't.


\subsection{Wine Quality}

The wine quality data set~\cite{Cortez2009} contains 6,497 samples and is described by 12 physicochemical features, including fixed acidity, residual sugar, and alcohol. The goal is to predict the quality of wine. We also know what kind of wine it is, red or white. As before, we generate a two-dimensional t-SNE embedding of the data set using parameter values metric=cosine, perplexity=500, exaggeration=2. We then explain the resulting embedding using VECA in terms of the original data features. The top four contrastive explanations and the top four descriptive explanations are shown in Fig.~\ref{fig:wine_explanations}.

\begin{figure*}[tb]
  \centering
  \includegraphics[width=\textwidth]{wine_explanations.pdf}
  \caption{We construct a t-SNE embedding of the wine quality data set and apply VECA to automatically obtain an explanation of the embedding. We plot the top four visual explanations in terms of contrastive value in panels a-d and the top four visual explanations in terms of descriptive value in panels e-h. The contrastive explanations each show only a single variable, but are ranked in such a way as to show the most well-separated and spatially-localized input variables first. The decriptive expalantions depicted in panels e-h are no longer limited to a single input variable, but aim to show maximally-informative combinations of the derived, explanatory variables.}
  \label{fig:wine_explanations}
\end{figure*}

For instance, panels a and b show that different values of the \textit{Wine Type} and \textit{Chlorides} variables appear in distinct regions of the space, while the variables \textit{Total Sulfur Oxide} and \textit{Residual sugar} in panels c and d being to exhibit a small degree of overlap. We verify this hypothesis in Fig.~\ref{fig:wine_type_separation} by inspecting which samples are contained within each underlying region. The plot validates that there is minimal mixing between samples between red and white wines. The plot also validates that this in-between cluster is ineed somewhat mixed.

\begin{figure}[ht]
  \centering
  \includegraphics[width=\linewidth]{wine_type_separation.pdf}
  \caption{We plot each region from Fig.~\ref{fig:wine_explanations}. Panel a highlights the points corresponding to red wine, while panel b highlights the points corresponding to white wine. We see that there is minimal mixing between the two wine types. We also observe the small in-between cluster contains a rough mix of 50\% white wine and 50\% red wine.}
  \label{fig:wine_type_separation}
\end{figure}

Descriptive visual explanations can also be useful for discovering correlations between explanatory variables. For instance, the blue region in the left had side of panel e contains three explanatory variables: \textit{wine type = 'red'}, \textit{total sulfur dioxide < 60.13}, and \textit{0.06 < chlorides < 0.13}. We can then quickly conclude that most red wines contain lower levels of total sulfur dioxide than white wines and that its levels of chlorides is between 0.06 and 0.13. We can consult the discriminative eplanations to determine whether these levels of chlorides is low or high. Inspecting panel b, we can conclude that this is a middle-range value of chlorides.

Fig.~\ref{fig:wine_explanations}.a indicates that the two types of wines are clearly separated from one another in the embedding. This is particularily interesting, because this feature was not used to construct the embedding. This indicates that there are big differences between the chemical properties of red and white wine. There is also a gray-ish cluster in the upper area between the two large clusters that seems to contain a small region containg white wines. However, a good number of data points are left outside any region. This may indicate that this region si more mixed, and requires further investigation.

We also demonstrate that our discretization proceedure alleviates the problem of outliers values skew color scales. A common approach for explaining embeddings in terms of their original input features is to simply color each point in the scatter plot in according to its feature value. However, this can made difficult when the feature in question contains outlier values which skew the entire color scale to one side, resulting in a very uneven distribution of colors.
For instance, Fig.~\ref{fig:wine_discretization}.a shows the distribution of the values of the \textit{Residual Sugar} input variable. Notice that histogram is skewed heavily to one side because of a small number of outliers in the right-hand side of the plot. The corresponding scatterplot is also not informative, as the points appear to be more-or-less colored in the same violet color. A common remedy to this problem is to apply a log-transformation, but this is not always effective, and increasive cognitive load on the analyst, as now they must think about variable values in terms of ther log-scale. Fig.~\ref{fig:wine_discretization}.b shows the log-transformed values of the original \textit{Residual Sugar} input variable.

\begin{figure}[ht!]
  \centering
  \includegraphics[width=\linewidth]{wine_discretization.pdf}
  \caption{We compare our approach to the typical approach to explaining embedding with the original input variables using scatter-plot color-coding. We use the \textit{Residual Sugar} variable from the wine quality data set~\cite{Cortez2009} as an example. The top-left panel shows a typical color-coding scheme, where the color scale is skewed as a result of a few outliers. Consequently, the plot is not informative. We apply a log-transform to fix this issue in the top-right panel, but this now requires reasoning about the values in log-scale. The lower panels show our discretization proceedure without any data transformations. Due to discretizaiton, the visualization does not suffer from this problem, while the final discretization in the bottom-right panel additionally merges variable values into three bins corresponding to `low', `medium', and `high` concentrations of `Residual Sugar'.}
  \label{fig:wine_discretization}
\end{figure}

Applying our discretization approach mitigates this problem. Fig.~\ref{fig:wine_discretization}.c shows that applying any kind of discretization will limit the effects of outlier samples. These often get put into one bin and have minimal negative effect on the coloring of the resulting scatterplot. Notice that the scatterplot in Fig.~\ref{fig:wine_discretization}.c looks similar to that in Fig.~\ref{fig:wine_discretization}.b, however, we are still able to reason about the variable values in terms of their original scales. Applying our merging proceedure merges spatially-overlapping bins together, resulting in a cleaner overall visualization. The scatter plot in Fig.~\ref{fig:wine_discretization}.d shows three distinct bins, where the right hand side of the scatter plot seems to be characterized by higher values of \textit{Residual Sugar}, which transition to lower values as we move to the left-hand side. Notice that the outlier values were all correcly bundled with the higher values.

\subsection{Forest Covertype}

We here adopt a similar evaluation setting as Sohns et al.~\cite{Sohns2022}, as it proves instructive and shows how visual explanations can be used to understand deep models and uncover the types of relationships learned between the input variables and target variables.

The forest cover type data set~\cite{Blackard1999} contains 581,012 samples described by 12 features. The dataset is primarily used for supervised learning, where we try to predict the seven different types forest. The features include things like elevation, distance to roadways, soil type.

As in the previous two examples, we generate a two-dimensional t-SNE embedding using parameter values metric=cosine, perplexity=500, and exaggeration=4. We then explain the resulting embedding using VECA in terms of the original data features. The top four contrastive explanations are shown in Fig.~\ref{fig:covertype_explantions}.

\begin{figure}[htb]
  \centering
  \includegraphics[width=\linewidth]{covertype_contrastive.pdf}
  \caption{Forest covertype contrastive explanations}
  \label{fig:covertype_explantions}
\end{figure}

Examining the contrastive layouts in Fig.~\ref{fig:covertype_explantions}, we see that the clusters are primmarily grouped by Wilderness Area, i.e., the national park where the samples were collected. This indicates that the trees in these particular national parks are in fact more similar to one another than trees in other national parks. However, this may also be undesired if we want to predict covertypes on new national parks. Fig.~\ref{fig:covertype_explantions}.b-c reveal that \textit{Elevation} and the \textit{Hillshade 3pm} variables also contribute sample similarity.

As our primary goal with this data set is prediction of the Forest Covertype, it is inspiring to see that the Cover Type variable appears to be at least somewhat localized in the space. Fig.~\ref{fig:covertype_explantions}.d shows two distinct groups of forest cover types, the orange group corresponding to \textit{Cottonwood/Willow}, \textit{Douglas-fir}, and \textit{Ponderosa Pine}, the blue group to the remaining four cover types. This indicates that any machine learning model we construct will likely have little difficulty separating instances between these two groups of forest types. Differentiating samples from different cover types within these groups may, however, prove more challenging. This is not necessarily the case, as the embedding was constructed using all the available input features, however, the model may determine that some of these input features are not important for the prediction task, and may ignore them outright. In the next section, we do exactly this and learn a deep neural network, and use VECA to investigate the types of relationships the model learns between the input variables and target class.

\subsubsection{Deep Forest Covertype Embeddings}

One common usage of two-dimensional embeddings is model validation. This is particularily useful in deep learning, where we can exmaine a two dimensional representation of the learned latent embeddings, and inspect whether the model has learned to differentiate between the classes of interest. In deep models, the mapping between the learned latent embeddings and the original input variables are often too complex to reason about directly. However, it can still make sense to inspect a two-dimensional visualization of the learned embeddings as these can shed light into the types of relationships between input variables that the deep-learning model learned and which input variables might be important for the overall prediction.

We illustrate model validation by training a four-layer neural network on the forest covertype data set. We use the same data split as in the original publication~\cite{Blackard1999}. More concretely, we use two hidden layers with sizes (256, 128) using ReLU activation units. We optimize the model using the Adam optimizer for 2,000 epochs. Our final model achieves 48\% predictive accuracy on the seven classes, which is lower than the 70\% predictive accuracy reported by Blackard et al.~\cite{Blackard1999}. We note that we did not spend any time searching for the optimal architecture or tuning hyperparameters. Our goal here is to demonstrate that VECA can be useful tool in understanding the types of relations deep-learning models learn and what kind of mistakes they are likely to make.

As before, we generate a two-dimensional t-SNE embedding using the same parameters. This time, however, the input to our dimensionality reduction algorithm is not the original data features, but the latent embedding before the final classification layer in our neural network. We then use VECA to explain this embedding with regard to the original data features.

Our primary variable of interest is the \textit{Cover Type} variable, as this is the variable we are trying to predict. Ideally, the two-dimensional embedding woudl reveal seven clusters, one for each class category, indicating perfect separation between the different classes. However, in most real-world problems, this is not the case. Fig.~\ref{fig:covertype_model}.a shows our the t-SNE embedding of the latent representation, annotated with explanatory variables corresponding to forest Cover Type. The plot indicates no clear clusters, but rather an elongated cluster containing all the data points. The VECA annotations reveal that even though the model was unable to learn clear boundaries between the data classes, it has learned to diffentiate between some groups of Cover Types. For instance, the oragne region corresponding to Cottonwood/Willows, Douglas Firs, and Ponderosa Pines are on the completely opposite end of the embedding than samples corresponding to Krummholz. This indicates that the model should be able to do a good job differentiating between these two classes. We can validate this hypothesis by inspecting the confusion matrix shown in Fig.~\ref{fig:covertype_model}.b. Indeed, the model has made no misclassifications between these two groups of classes. On the other hand, Fig.~\ref{fig:covertype_model}.a indicates that the model may have a hard time differentiating between Krummholz and Spruce/Fir type forest covers. And indeed, inspecting the confusion matrix confirms our suspicion: while our neural network is able to classify Krummholz instances with a high degree of accuracy, the samples that it does misclassify are almost always classified as Splruce/Fir cover types.

\begin{figure}[htb]
  \centering
  \includegraphics[width=\linewidth]{covertype_model.pdf}
  \caption{Forest covertype model. The abbreviated class names in the confusion matrix correspond to Cottonwood/Willow (CW), Douglas-Fir (DF), Ponderosa Pine (PP), Aspen (AS), Lodgepole Pine (LP), Spruce/Fir (SF), and Krummholz (KR).}
  \label{fig:covertype_model}
\end{figure}

Having investigated how well the model appears to be able to perform its classification task, we would next be interested in what kinds of relationships the model has learned between the input variables and the target class. While it is possible to inspect the model weights and deduce the feature importances directly, this often requires the use of specialized techniques. Instead, a visual explanation provides a quick and easy way to see what's going on under the hood. We show the top-four contrastive layouts in Fig.~\ref{fig:covertype_model_contrastive}.

\begin{figure}[htb]
  \centering
  \includegraphics[width=\linewidth]{covertype_model_contrastive.pdf}
  \caption{We inspect the top-four contrastive layouts of the learned embeddings.}
  \label{fig:covertype_model_contrastive}
\end{figure}

Fig.~\ref{fig:covertype_model_contrastive}.a indicates that the model may have learned a relationship between the soil type and the cover type.  This indicates that having a certain soil type is important for identifying Krummholz cover types. Fig.~\ref{fig:covertype_model_contrastive}.b reveal that model has learned a relationship between the elevation and the predicted class. Fig.~\ref{fig:covertype_model_contrastive}.c shows that the wilderness area variable, i.e., the geographic location from which each sample was collected, also correlates with the latent embedding. This could indicate overfitting if, for instance, our goal way to develop a model which could classify forest covertype regardless of geographic location. If our goal, on the other hand, was to classify only instances from these four geographic areas, this may signal that some geographic areas are simply more likely to contain different forest cover types. The visual explanation provides a quick insight into this.

Our initial embedding in Fig.~\ref{fig:covertype_explantions} identified the \textit{Hillshade 3pm} input variable as one of the top contrastive variables. However, it seems that this feature was not as important for the prediction task, and was not identified as one of the top-four most important contrastive explanations in Fig.~\ref{fig:covertype_model_contrastive}. On the other hand, the \textit{Soil Type} variable appears at least somewhat useful for the prediction task, while it wasn't as important for explaning the original embedding.

We emphasize that these explanations are not definitive, as one would have to inspect the model weights to validate this claim. However, a spatial correlation in the embedding space indicates the model has assigned non-zero weights to these features, and has learned some relationship between the input variable and target class, as otherwise, the attribute would be decorrelated with the embedding space. So, if the variable is spatially localized in some space, it is likely that the model is using it for prediction.

\section{Discussion and Future Work}

The region construction step of approach could be replaced by alpha-hulls from Sohns et al.~\cite{Sohns2022} or any other one of the embedding enrichment schemes proposed by Nonato and Aupetit~\cite{Nonato2018}. Alpha-hulls may even benefit in terms of purity. However, this could be problematic if the users chooses to insert new data points into existing embeddings. Modern implementations of t-SNE~\cite{Policar2019} and UMAP~\cite{McInnes2018} both enable users to insert out-of-sample data points into existing embeddings, and the tight boundary of alpha hulls might leave some points outside of the ecompassed region.

Using kernel density estimates to extract regions can also miss smaller clusters of data points. Due to the nature of kernel density estimation, and our choice to extract regions at a prespecified contour level, some small clusters could easily be missed, even if they are compeltely enriched with a single variable value, simply because there are not enough data points in the cluster. Developing alternative techniques for region estimation is a good avenue for future work.

Our approach achieves scalability in the number of data points through sampling. By default, we limit the number of data points to 5,000 and use those to estimate regions and contruct visual explanations. Our approach works quite well even when this number is increased to e.g. 10,000, but the results are largely the same. Our approach is generally not limited by the number of data points, but rather, the number of different variables. For each variable, we perform several computatiation intesive tasks. We first apply K-Means discretization to each variable, then perform kernel density estimates for each variable. We then determine the number of sample data points that fall within each region . Finally, each region undergoes an iterative post-hoc iterative merging process which primarily depends on the number of discretization bins or the number of different categories in the categorical variables. Data sets containing thousands to tens of thousands have become widespread in fields such as bioinformatics, where non-linear dimensionality reduciton methods are routinely used to inspect transcriptomics data. Developing more scalable methods capable of generating visual explanations for data sets containing thousands of variables would be of great interest.

While the focus of our VECA is to create a fully-automated pipeline for generating visual explanations of embeddings, one can easily envision an interactive system where these kinds of visual explanations could be explored in more detail by the user. For instance, a user presented with a descriptive explanation such as the one in Fig.~\ref{fig:wine_explanations}.e may discover the blue region corresponds to red wine, low levels of sulfur dioxide, and certain levels of chlorides. However, they may then wonder where in the plot high levels sulfur dioxide appear, in which case the user would be presented with a contrastive explanation of this variable as in Fig.~\ref{fig:wine_explanations}.c. The user may similarily wonder where exactly the three regions contained within the blue region occur, and may wish to inspect the subregions, as seen in Figs.~\ref{fig:covertype_model_contrastive}.c-f. Alternatively, the user may also be intersted in the purity of the region, and may wish to inspect a plot that highlights exactly which data samples exhibit the particular explanatory variable, and which such samples are missing from the regions, similar to what is shown in Fig.~\ref{fig:wine_type_separation}. Such a user interface could seamlessly be incorporated into existing visual analytics tools such as Orange~\cite{Demvar2013}.

\section{Conclusion}

This paper presents VECA, a visual explanation framework designed to automatically generate visual explanations for two-dimensional embeddings. Explanations are generated in terms of any variables of choice, most commonly, the input variables used to generate the embedding. VECA is able to generate two types of visual explanations: contrastive explanations, which aim to find the most informative input variables, and descriptive variables, which aim to describe as much of the space as possible using different variables or combination of variables.
Our approach involves a novel discretization scheme based on the spatial proximities between differnt discretization bins in the embedding. VECA generates multiple possible visual explanations. In contrastive explanations, we develop a novel visual explanation ranking scheme, prefering layouts with little overlap and which are as informative as possible. For descriptive explanations, we frame the explanation consturction process as a graph-independent set problem, and develop a novel ranking scheme that prefers diverse and informative visual explanations.
We demonstrate the utiliy of our approach on three data sets, of increasing complexity. We also demonstrate how VECA can be used to gain an understanding into deep networks, uncover the types of errors these methods are likely to make, and what kinds of relationships they are likely to have learned.

We also release our reference, Python implementation of VECA. VECA is available on GitHub and can be installed via PyPI. VECA is easy to use, and we have worked hard to make the parameters easy to understand. 

Overall, our work contributes to the growing field of interpretable machine learning and offers a new perspective on how to explain non-linear embeddings in terms of their original features. It also provides a new exploratory method for describing the behaviour of deep neural networks models.

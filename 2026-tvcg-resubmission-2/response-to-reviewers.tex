\subsection*{Reviewer 1}

\reviewc{r1q1}{Uniqueness in Abstract and Introduction

The abstract now emphasizes that VERA filters, merges, and ranks candidate explanations rather than simply encoding feature values, and the introduction adds useful framing about the intended analysis setting. This is an improvement.

However, the differentiation is still stated in general terms. For example, neither the abstract nor the introduction articulates VERA's essential distinction from the most closely related explanation-generation methods (e.g., Sohns et al. and the attribute-based family). I would still encourage the authors to state, early and concretely, what VERA does that these prior methods do not, for instance, incorporating multiple attributes within a single annotated region and why such incorporation is important.}

\answer{%
We agree and thank the reviewer for the concrete suggestion, which we have adopted. The abstract now states that VERA describes each region by the combination of features that jointly characterize it. In the Introduction (Section~\ref{sec:intro}), the paragraph starting with ``In this paper, we propose \ldots'' now contrasts VERA with rangesets and the attribute-based explanation, and explains why annotating each region with all features that jointly characterize it is important.

The new figure (Fig.~\ref{fig:related_methods}) illustrates this difference on the same embedding. We also include a detailed comparison of rangesets and VERA in Section~\ref{sec:supp-rangesets} of the supplement.
}

\reviewc{r1q2}{Comparison with existing visual explanation methods

I appreciate that the authors now cite Sohns et al. [23], discuss it in Related Work. This addresses the citation omission.

My core concern, however, is not fully resolved: the user study still compares VERA only against Orange, a general-purpose interactive tool. The revision does not include an explicit comparison (even small-scale or qualitative) against methods explicitly designed for explaining embeddings, and no rationale for this omission is given. The authors included rangesets-style variant output images in the supplementary material (GitHub repository); however, these figures are difficult to locate and compare with VERA as they are not in the main manuscript. More importantly, they do not provide an explicit qualitative evaluation of how VERA's benefits differ from this variant.

Consequently, the claim of advantage over purpose-built approaches remains unsupported. A focused qualitative comparison (e.g., a set of Sohns et al. visualizations versus a single VERA panel on the same embedding) would substantially strengthen the contribution, even without a full user study.}

\answer{%
We agree that the previous revision did not compare VERA with methods designed specifically for explaining embeddings. The manuscript now includes a new figure (Fig.~\ref{fig:related_methods}) comparing the outputs of six related embedding explanation methods, including rangesets. We also include a dedicated section in the supplementary material (Section~\ref{sec:supp-rangesets}) discussing the similarities and differences between rangesets and VERA. Figs.~\ref{fig:supp-rangeset-contrastive-abalone} and \ref{fig:supp-rangeset-contrastive-attrition} show a visual comparison between the two approaches. The accompanying GitHub repository includes several more visual examples comparing the two methods, as before.

Fig.~\ref{fig:related_methods} shows the main differences. The linked-view methods (b--d) explain a given clustering, rangesets (e) show one feature at a time, and the attribute-based explanation and column selection (f, g) produce a single explanation. VERA instead annotates each region with all features that jointly characterize it (h). We did not include the methods of Fig.~\ref{fig:related_methods}.b--g in the user study because four of them (b--e) were proposed as components of larger interactive systems (Section~\ref{sec:related_work}), and Orange reproduces several of them in a single tool familiar to the participants.

Our rationale for choosing Orange as the baseline in the user study is given in Section~\ref{sec:user-study:design}:

\copyquote{Although not explicitly designed for interpreting embeddings, Orange includes standard visualization tools for exploring two-dimensional embeddings. Many related approaches based on feature distribution plots [31], [35] and discriminative models [13], [21] can be easily reproduced in Orange using only a handful of widgets.}

and

\copyquote{Prior to the study, students were already familiar with Orange but not with VERA explanations, so we provided a brief tutorial on both tools before beginning the experiment. This prior familiarity with Orange reduced additional interface-learning overhead for the interactive baseline.}

We further discuss Orange in Section~\ref{sec:supp-orange}, where we include example workflows that reproduce several interactive embedding explanation approaches. More examples, as well as the corresponding Orange workflow files, are included in the accompanying GitHub repository. This is also mentioned in Section~\ref{sec:user-study:design}:

\copyquote{We provide several example workflows in Section~\ref{sec:supp-orange}.}
}

\reviewc{r1q3}{Usefulness for high-dimensional data

The authors responded by narrowing the stated scope rather than demonstrating high-dimensional results. The introduction now targets ``tens to a few hundred variables,'' and the limitations section states that VERA is best suited for up to several hundred features. The practical scalability guidance I requested is now provided.

However, this ``best suited for'' claim is asserted but not demonstrated. The only data at that scale appears in the runtime experiment (Fig. 11), which measures computation time on synthetic data and does not show the resulting explanations. All usage scenarios with actual generated explanations use 33 features or fewer. Since the claim concerns visual readability and interpretability (not runtime), I would ask the authors to substantiate it with at least one example showing VERA's explanations on a dataset with a few hundred features, or to qualify the claim accordingly. This is especially important given the authors' own observation that long descriptor lists and label overlap degrade the descriptive explanations, problems that would plausibly emerge well before several hundred features.}

\answer{%
We agree that our previous version did not adequately demonstrate the behavior of VERA on datasets with larger numbers of features. The revised manuscript and supplement now show VERA's explanations of five datasets with several hundred features.

The newly added Fig.~\ref{fig:related_methods} shows several embedding explanation methods run on a dataset comprising 239 features. VERA subsequently expands these features into 1,194 explanatory variables from which the visual explanations are generated. Although this figure includes only a single VERA panel, we include a full VERA explanation of this dataset in Fig.~\ref{fig:supp-football}. We include it only in the supplementary material due to space constraints. We also include VERA explanations of four single-cell RNA-seq datasets in Fig.~\ref{fig:supp-single-cell}. For each dataset, VERA starts from the 500 genes with the largest Pearson-residual variance and selects the few that characterize each region.

As the reviewer noted, long descriptor lists result in substantial label overlap and make the visualization difficult to read.
Section~\ref{sec:scalability} suggests that this could be mitigated in the future by using large language models (LLMs) to summarize long descriptor lists, or by integrating VERA into an interactive interface.
Our present solution is to optionally limit the number of descriptors shown in each label. Section~\ref{sec:scalability} now states:

\copyquote{For annotations showing a large number of descriptors, labels can optionally be limited to the highest-ranked descriptors, with the number omitted clearly indicated, so that a label is never mistaken for the full conjunction (Fig.~\ref{fig:related_methods}.h).}

We discuss long descriptor lists further in our responses to Comments~\ref{r3q5} and~\ref{r3q6}.
}

\reviewc{r1q4}{Missing reasonings for algorithmic design.

This concern is largely addressed. The added rationales for the default parameters, the explicit definition of the human-attention score, the justification of the aggregation strategy, and the new parameter sensitivity study together resolve the earlier impression that the design choices were arbitrary.

One minor item remains: the region-merging threshold is described as ``user-specified'' with a ``conservative default'' but without a concrete value or selection procedure, and ``nearly perfect'' overlap in the contrastive merge is still not precisely defined.}

\answer{%
We now explicitly state both values in Section~\ref{sec:methods}. For the post hoc merge, Section~\ref{sec:post-hoc-merge} reads:

\copyquote{A pair of regions is merged when their maximum overlap exceeds a user-specified threshold, $0.8$ by default, so that clearly redundant regions are consolidated while nearby but distinct structures remain separate.}

For the contrastive merge, Section~\ref{sec:contrastive:explanation-construction} now replaces ``nearly perfectly overlapping'' with a precise criterion:

\copyquote{To merge region annotations associated with two features $f_1$ and $f_2$, each region annotation $e_i \in f_1$ must have a counterpart $e_j \in f_2$ that covers nearly the same samples, i.e., whose Jaccard similarity with $e_i$ exceeds $0.95$ by default.}
}

\reviewc{r3q1}{I agree with the authors that VERA is doing more than explanations by single attributes, such as Sohns et al.'s work, or also DimReader. Still, the explanations are done in a univariate setting and then combined. Hence, the approach can only extract axis-aligned regions of interest (in the high-dimensional space). Clusters are generally not axis-aligned regions in a multivariate setting. Hence, the approach extracts regions of interest similar to what one could achieve by brushing on parallel coordinates. While this is a drawback, it is also a feature, as one could then describe each region by a logical AND-combination of 1D rules.}

\answer{%
We agree that this is both a limitation and a feature, since, as the reviewer notes, the descriptors are combinations of AND rules.
Section~\ref{sec:scalability} now states:

\copyquote{Finally, the regions VERA finds are, by construction, conjunctions of one-dimensional rules, i.e., axis-aligned boxes in the space of explanatory variables. This is a limitation, since multivariate structure need not be axis-aligned and a diagonal cluster is then described by several coarse rules, but it is also what makes every region readable as an AND-combination of conditions an analyst can verify.}
}

\reviewc{r3q2}{The authors changed the wording about the dimensionality of the data, going from thousands to hundreds. I don't think that matters. What matters is how many dimensions are required to describe the regions. Here, only a few dimensions can be used. Using hundreds of dimensions for explanations is not feasible. However, I would think that in a dataset with hundreds of attributes, there are generally more than a handful of attributes that are of interest. Hence, the scalability of the approach to high dimensionality is very limited.}

\answer{%
We agree that long region descriptions are a limitation, which Section~\ref{sec:scalability} discusses. VERA, however, ranks descriptors so that the most informative come first. On the football dataset with 239 features, labels showing only the two highest-ranked descriptors already identify goalkeepers, defenders, and midfielders and forwards (Fig.~\ref{fig:related_methods}.h), and each label states how many descriptors are omitted. See also our responses to Comments~\ref{r1q3} and~\ref{r3q5}.
}

\reviewc{r3q3}{The parameter choices remain unspecific. For example, the authors talk about ``practical middle ground'' and that ``nearby but distinct structures remain separate''. On the other hand, they have conducted a thorough parameter sensitivity study and provided practical guidance. Unfortunately, both belong to the supplementary material only, with the issue described above.}

\answer{%
We now explicitly list VERA's main parameters and their defaults in Table~\ref{tab:supp-parameters}.
We also state the key default values explicitly in the manuscript. For the post hoc merge, Section~\ref{sec:post-hoc-merge} states:

\copyquote{A pair of regions is merged when their maximum overlap exceeds a user-specified threshold, $0.8$ by default, so that clearly redundant regions are consolidated while nearby but distinct structures remain separate.}

For the contrastive merge, Section~\ref{sec:contrastive:explanation-construction} now states:

\copyquote{To merge region annotations associated with two features $f_1$ and $f_2$, each region annotation $e_i \in f_1$ must have a counterpart $e_j \in f_2$ that covers nearly the same samples, i.e., whose Jaccard similarity with $e_i$ exceeds $0.95$ by default.}

We state the default choice of $k$ for $k$-means binning in the footnote in Section~\ref{sec:discretization}:

\copyquote{We use $k=5$ by default, although we have found VERA to be fairly robust to the choice of $k$ due to the subsequent post hoc merging step described in Section~\ref{sec:post-hoc-merge}.}

Due to space constraints, we leave the parameter study in the supplementary material. We discuss the most important parameters in the accompanying PDF, while the full parameter sweep can be found in the accompanying GitHub repository, as before.
}

\reviewc{r3q4}{The authors have now clarified that they used k-means for univariate binning. That's much better than equidistant binning. Still, there are also methods (such as multi-Otsu thresholding) that do not require the setting of k. How was k actually chosen here?}

\answer{%
We agree that multi-Otsu thresholding would be an interesting alternative to our $k$-means binning approach. Due to our post hoc region merging step, we found VERA to be fairly robust to different discretizations, as overfragmented regions that occupy similar regions of the embedding space are subsequently merged back together. Fig.~\ref{fig:supp-param-bins} shows this qualitatively for different values of $k$ in our approach. While we therefore agree that alternative discretization approaches may also be viable, we expect them to yield similar explanations.

We now write in the footnote in Section~\ref{sec:discretization}:

\copyquote{We use $k=5$ by default, although we have found VERA to be fairly robust to the choice of $k$ due to the subsequent post hoc merging step described in Section~\ref{sec:post-hoc-merge}. See Fig.~\ref{fig:supp-param-bins} for more details.}

We chose $k=5$ for two reasons, which the supplement details (Section~\ref{sec:supp-parameters}). Five bins typically allow enough flexibility without producing so many regions that they burden the reader, and they resemble the five-point Likert scale familiar to most users, so the regions of a numeric feature read as levels from very low to very high.
}

\reviewc{r3q5}{The method still has the disadvantage of misleading labels, when the labels do not provide the full logical ANDs of the region definition. This should either be avoided or made explicit, e.g., by visual encodings.}

\answer{%
We agree that a label that shows only part of the conjunction is misleading unless the truncation is visible. This is now made explicit, in two ways. The label states how many descriptors were omitted, and the points inside a region are shaded by how many of the region's descriptors they satisfy.

Section~\ref{sec:scalability} now states:

\copyquote{For annotations showing a large number of descriptors, labels can optionally be limited to the highest-ranked descriptors, with the number omitted clearly indicated, so that a label is never mistaken for the full conjunction (Fig.~\ref{fig:related_methods}.h). Points within each region are shaded by the fraction of its descriptors they satisfy, so that membership strength remains visible even when the label lists only a few descriptors.}
}

\reviewc{r3q6}{Also, the issue of occlusion with many labels is an issue. I think long explaining rules are also difficult to understand. A visualization of the rules, e.g. in coordinated views, may be helpful and would make the longish labels obsolete. I don't think that VERA needs to be static. Why not provide more details on demand? BTW, I agree with another reviewer that LLMs cannot make the explanations shorter without losing relevant information.}

\answer{%
We agree that many labels cause occlusion and that long rules are hard to read. We also agree that VERA need not remain static, and that an interactive interface with coordinated views and details on demand would address many of these concerns. The revised Section~\ref{sec:scalability} now names this as future work:

\copyquote{Future work could address these issues by integrating VERA into an interactive tool, where full descriptor lists and feature distributions are available on demand, or by leveraging large language models (LLMs) to generate concise summaries of lengthy region descriptors.}

The Conclusion similarly lists integration with interactive analytics platforms among promising directions:

\copyquote{Extending VERA to handle diverse data modalities, including image, video, text, and graph data, improving scalability to very large feature sets through feature aggregation or abstraction, and exploring integration with interactive analytics platforms all represent promising directions.}

In this manuscript, however, our explicit aim is static visual explanations. Interactive tools for exploring embeddings are well studied, whereas static explanations have received less attention. We see the two as complementary, as stated in the Introduction:

\copyquote{Together, these contributions demonstrate that VERA's static visual explanations can effectively convey the essential insights of complex embeddings, offering a fast and accessible complement to interactive data exploration.}

Regarding LLMs, we agree that a summary cannot replace the full list of descriptors. We see it instead as a short entry point to an explanation whose full rules remain available. Several recent publications show that LLMs can produce useful cluster annotations, for example topics from keywords in text data~\citep{Kozlowski2024,Piper2025} and descriptions of clusters in general and tabular data~\citep{Preiss2024,Hong2025,Buchmuller2026}.
Since our initial submission, we have developed a prototype that summarizes VERA's descriptor lists in this way, with promising results. As this is beyond the scope of the present manuscript, we plan to report it in a future publication.
}

\reviewc{r3q8}{I think an ablation study on which ranking criterion adds how much importance would have provided additional insight.}

\answer{%
We agree that an ablation study would provide additional insight. Our ranking criteria are grounded in findings from the social sciences~\citep{Miller2019} and in our experience with the datasets we explored during development. We combine them because none performed reliably on its own, as Section~\ref{sec:contrastive-selection} states:

\copyquote{Because no single metric reliably produced good rankings across datasets, we aggregate them using a weighted mean-rank strategy. This treats the criteria as complementary heuristics and avoids relying on any one metric alone.}

The default weights of the criteria are listed in Table~\ref{tab:supp-parameters}.

Removing one criterion at a time and measuring how the ranking changes would be straightforward. Determining whether the resulting ranking is better or worse, however, requires a judgment of explanation quality that no ground truth provides. A meaningful ablation would therefore require a dedicated user study that asks which explanations people find most informative. Such a study could also inform explanation design beyond VERA, in explainable AI more broadly, but it is beyond the scope of this revision and we leave it to future work.
}

\reviewc{r3q9}{The authors now state that they ``downweight poorly mapped samples during KDE estimation''. That is interesting, but raises questions. How exactly is this done? By how much are they downweighted? What is the impact thereof? How does this affect the outcome?}

\answer{%
We agree that our description of how distortion metrics can be incorporated into VERA explanations was lacking. We now describe distortion weighting in more detail in Section~\ref{sec:supp-distortion} as well as show examples in Figs.~\ref{fig:supp-distortion-abalone} and \ref{fig:supp-distortion-attrition-pca}. We decided to include this only in the supplement as it is not central to our exposition of VERA and due to space constraints. The corresponding section in the main manuscript now reads:

\copyquote{When sample-wise distortion measures are available, we downweight poorly mapped samples during KDE estimation, making spurious regions in distorted parts of the embedding less likely to be extracted. We describe this in more detail in Section~\ref{sec:supp-distortion}.}
}

\reviewc{r3q10}{The authors provided more details on computational scalability. That is laudable, but the main issues are visual scalability due to overplotting and scalability with the number of variables used for the explanations.}

\answer{%
We agree that visual scalability and the number of variables in an explanation are important limitations. However, we consider computational scalability no less important, since an explanation that takes too long to compute will not be used. All three are needed for VERA to be practical.

Section~\ref{sec:scalability} discusses both limitations:

\copyquote{Visual limitations primarily affect descriptive explanations, especially when the feature count is large. [\ldots] [L]ong descriptor lists impose a cognitive burden on users [\ldots] [and] consume screen space, leading to visual clutter: labels may overlap with each other or with data points, extend off-screen, or otherwise obstruct the view.}

The new Fig.~\ref{fig:related_methods}.h shows this limit on the football dataset, with 239 features:

\copyquote{Each of its regions is characterized by over two hundred descriptors, so each label shows only its two highest-ranked descriptors followed by the number of omitted descriptors, e.g., `(+266 more)'.}

We discuss the truncated labels in our response to Comment~\ref{r3q5}. An interactive front end with descriptor lists on demand is a natural extension, which we discuss in our response to Comment~\ref{r3q6}.
}

\reviewc{r3q11}{While the user study does not show a major gain in accuracy, the participants were significantly faster, which shows the benefit of the approach.}

\answer{%
Yes, we agree with this reading of the results. Accuracy was comparable, while participants needed about 30\% less time with VERA, which we consider the practically meaningful result (Section~\ref{sec:user-study:results}).
}
